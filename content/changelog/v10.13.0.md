This release makes `choice` fields with many options easier to work with, fixes dropped characters
while typing in the editor panel, and fixes the extension hanging in Astro projects.

## Highlights

- The new `searchable` property turns a `choice` field into an input you can filter by typing.
- Typing in `string` and `wysiwyg` fields no longer drops characters when the front matter updates
  are slow.
- The extension no longer hangs after initialization in Astro projects when the Node.js lookup fails.

## Searchable choice fields

Issue [#1061](https://github.com/estruyf/vscode-front-matter/issues/1061) adds the `searchable`
property to the `choice` field. Scrolling through a dropdown works for a handful of options, but not
when your field has dozens of them. With `searchable` set to `true`, the dropdown is replaced by an
input, and typing filters the choices on their title and ID.

```json
{
  "title": "Country",
  "name": "country",
  "type": "choice",
  "searchable": true,
  "choices": [
    { "id": "be", "title": "Belgium" },
    { "id": "nl", "title": "Netherlands" },
    { "id": "fr", "title": "France" },
    { "id": "de", "title": "Germany" }
  ]
}
```

The property is opt-in and works together with `multiple`, so you can search and pick several
values from the same list.

> **Info**: Check the [choice field documentation](/docs/content-creation/fields#choice) for more information.

## No more dropped characters while typing

Issue [#1062](https://github.com/estruyf/vscode-front-matter/issues/1062) fixes `string` and
`wysiwyg` fields losing characters, and feeling sluggish, when you typed faster than the front matter
update round trip. This mostly showed up on larger files or slower machines, where the echo of an
older update could overwrite what you had typed since.

The fields now keep track of the value they sent, so they recognize their own updates and never throw
away your pending edits.

## Astro projects no longer hang

Issue [#1064](https://github.com/estruyf/vscode-front-matter/issues/1064) fixes the extension hanging
after initialization in Astro projects when the Node.js lookup failed. Front Matter CMS now logs the
error and continues without the Astro content collections, instead of waiting forever.

Thanks to [Matt Van Horn](https://github.com/mvanhorn) for the fix.
