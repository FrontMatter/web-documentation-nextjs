This release is all about reliability. Custom scripts no longer run through a shell, the dashboard
and panel do less work, and a large batch of fixes makes sure your edits, settings, and content end
up where you expect them.

## Highlights

- Custom scripts receive their arguments without going through a shell, which fixes a command
  injection vulnerability. On Windows, this comes with a few breaking changes.
- The dashboard, panel, and preview only refresh when a relevant setting changes, and the media
  dashboard scans your files once instead of twice.
- Edits in the panel are no longer lost or reverted when updates overlap or when you switch files
  while typing.
- The extension no longer rewrites your content types, `pageFolders`, or the formatting of
  `frontmatter.json` when it updates a setting.

## ⚠️ Breaking changes on Windows

Issue [#1067](https://github.com/estruyf/vscode-front-matter/issues/1067) fixes an OS command
injection in custom scripts ([GHSA-w6cx-493p-x4jx](https://github.com/estruyf/vscode-front-matter/security/advisories/GHSA-w6cx-493p-x4jx)).
Front matter values, file names, titles, script answers, and Copilot responses were added to a
command string, so a crafted value could break out of its quotes and run commands on your machine.

Custom scripts, placeholder scripts, and media scripts now receive these values as separate
arguments that are never interpreted by a shell. Your scripts get the same arguments as before, but
on Windows you need to check the following:

- `.cmd` and `.bat` commands like `npx`, `npm`, `yarn`, or `pnpm` can no longer be used as the
  `command`. Use `node` (or another executable) and point the `script` to the JavaScript file instead.
- Environment variables in the `command`, like `%USERPROFILE%`, are no longer resolved. Use the full
  path instead.
- PowerShell scripts receive the front matter JSON as is, no longer wrapped in single quotes.

```json {{ "title": "Before (no longer supported on Windows)" }}
{
  "title": "Generate social image",
  "script": "./.frontmatter/config/custom/scripts/social-image.ts",
  "command": "npx tsx"
}
```

```json {{ "title": "After" }}
{
  "title": "Generate social image",
  "script": "./.frontmatter/config/custom/scripts/social-image.ts",
  "command": "node --import tsx"
}
```

On macOS and Linux, nothing changes for your configuration.

Thanks to [Dostxodjayev Abdullox](https://github.com/squeeze440) for reporting the vulnerability.

> **Info**: Check the [custom actions documentation](/docs/custom-actions#settings) for more information.

## A faster dashboard and panel

Pull request [#1068](https://github.com/estruyf/vscode-front-matter/pull/1068) removes a lot of
unnecessary work:

- The dashboard, panel, and preview only refresh when a Front Matter, `git.path`, or Markdown editor
  setting changes, instead of on every VS Code setting change.
- Changes to images and other non-content files in your content folders no longer trigger a full
  re-parse of all your pages.
- Refreshing the media dashboard, uploading, or pasting media scans the media files once instead of
  twice, and images and videos are loaded lazily.
- Sites with many pages load faster in the dashboard, as cached pages are looked up by their path.
- The extension bundle is smaller and activates faster, as the unused GitHub credentials code
  (`@octokit/rest`) is removed.

## Your edits stay where you put them

Pull request [#1074](https://github.com/estruyf/vscode-front-matter/pull/1074) reworks how the panel
handles updates. When updates overlapped, an older value could come back and overwrite what you had
typed since. This affected `wysiwyg`, `slug`, `number`, `choice`, `datetime`, and relationship
fields, block fields, and the last characters you typed before switching files. All of these now keep
your changes.

The panel also writes to the right file. Before, front matter could end up in the focused file (for
example, a `.ts` file) instead of the file the panel shows.

The markdown `wysiwyg` field no longer rewrites its value when you open a file, and with
[#1077](https://github.com/estruyf/vscode-front-matter/pull/1077), editing it keeps the list bullets,
emphasis markers, and line endings the value already uses. A `-` bullet stays a `-` bullet,
`_italic_` stays `_italic_`, and `snake_case` no longer turns into `snake\_case`.

## Your settings stay untouched

Pull requests [#1069](https://github.com/estruyf/vscode-front-matter/pull/1069) and
[#1071](https://github.com/estruyf/vscode-front-matter/pull/1071) fix several cases where the
extension changed more of your configuration than it should:

- "Create template from current file" and project initialization no longer replace your content
  types or overwrite the framework, static folder, and preview host settings.
- Comments and formatting in `frontmatter.json` are kept when the extension updates a setting.
- Registering or unregistering a content folder no longer rewrites your `pageFolders` setting, and
  settings from `.frontmatter/config` files are no longer copied into `frontmatter.json`.
- Cancelling the remap command no longer deletes the tag or category from all your content.

### ⚠️ Breaking changes

- Custom scripts, placeholder scripts, and media scripts no longer pass front matter values, file paths, titles, answers, or Copilot responses through a shell. They are passed as separate arguments, which prevents command injection. Scripts receive the same arguments, with these differences on Windows:
  - `.cmd` and `.bat` commands like `npx`, `npm`, `yarn`, or `pnpm` are no longer supported as the `command`. Use `node` (or another executable) and point the `script` to the JavaScript file instead
  - Environment variables in the `command` like `%USERPROFILE%` are no longer resolved. Use the full path instead
  - PowerShell scripts receive the front matter JSON as is, no longer wrapped in single quotes
